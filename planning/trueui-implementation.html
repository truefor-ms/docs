TrueUI

Build and validate the shared library before application implementation.

Plan2026-11-07Markdown source

Status: first implementation workstream. Frontend and backend application implementation starts only after TrueUI reaches standalone readiness for the initial Form UI and Form Builder UI scope.

Scope

Build in ui: reusable presentation, component state, keyboard/focus behavior, tokens and fixture-based examples. Use the Form UI and Form Builder UI plans as requirements, not as parallel application projects.

TrueUI does not own product schema commands, publication, persistence, authorization or billing. Examples simulate application data and callbacks. Planning those contracts is allowed before the gate; implementing the application repositories is not.

Implementation order

7 Required advanced controls: combobox/multiselect, dates, upload presentation, rating/range and adapters Agreed initial extended fields Corresponding property controls Each included control has documented value/state contracts and isolated examples

9 Package, regression coverage and readiness review Stable consumer contract Stable consumer contract Versioned artifact works in an isolated consumer fixture; readiness accepted

Determine the required initial advanced-control scope before package 7. Record explicit deferrals against the two surface plans; do not treat basic inputs alone as a mature library. Field inventories remain planning references, not a requirement to finish every future integration before accepting the initial scope. Form payment fields retain their separate package.

Readiness evidence

The authoritative TrueUI readiness gate requires coverage of both surfaces, documented APIs and states, keyboard/accessibility and responsive checks, standalone examples, a consumable artifact and explicit acceptance.

Track each reusable requirement as planned, specified, implemented, verified or accepted, with its example and verification evidence. Mark a composition as simulated when application behavior is provided by fixtures. No readiness acceptance or completed component implementation is claimed by this document.

After acceptance

Start application foundations and subscriptions, then execute the frontend-owned steps in Form UI and Form Builder UI against the ready library and backend contracts. Subsequent component additions still belong in TrueUI; application business logic remains in frontend/backend.
